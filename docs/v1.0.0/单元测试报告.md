## 3. 测试重点

### 3.1 Code Review 修复项验证

| 修复项 | 测试覆盖 |
|--------|---------|
| B-1~B-4: 四层架构违规 | ✅ 所有 AppService 层均可独立 Mock DomainService 测试，验证四层架构合规 |
| B-5: 硬编码角色权限 | ⚠️ 依赖 StpUtil 静态方法，纯单元测试无法覆盖，需集成测试验证 |
| B-6: 文件上传类型/大小校验 | ✅ 8个上传测试覆盖：空文件、超10MB、exe/sh黑名单、无扩展名、jpg/pdf白名单 |
| B-7: 密码修改不验证旧密码 | ⚠️ 依赖 StpUtil 静态方法，需集成测试验证 |

### 3.2 参数校验边界覆盖

- **null 参数**：所有 AppService 的入参 null 检查
- **空字符串**：用户名/密码/角色名等必填字段空值校验
- **非法 ID**：0、负数、null 三种边界
- **状态值**：仅允许 0/1，非法值 2 被拒绝
- **文件大小**：11MB 超过 10MB 限制
- **文件类型**：exe/sh 被拒绝，jpg/pdf 在白名单中

## 4. 未覆盖说明

以下场景因依赖 sa-token 的 `StpUtil` 静态方法，在纯单元测试中无法 Mock，需在集成测试中验证：

1. **AuthAppService.login() 成功流程**：`StpUtil.login()` 需要有效的 sa-token 上下文
2. **AuthAppService.getCurrentUserRoles/Permissions()**：`StpUtil.getLoginIdAsLong()` 需要登录会话
3. **ProfileAppService.changePassword()**：`StpUtil.getLoginIdAsLong()` 需要登录会话
4. **ProfileAppService.getProfile()/updateProfile()**：同上
5. **FileAppService.upload() 完整流程**：`StpUtil.getLoginIdAsLong()` 需要登录会话

## 5. 结论

**通过** - 81个单元测试全部通过，AppService 层核心业务逻辑（参数校验、状态校验、文件上传安全校验、领域服务调用编排）均得到验证。依赖 sa-token 的场景需在集成测试阶段覆盖。
