## 3. 缺陷列表

| 缺陷编号 | 描述 | 严重程度 | 责任方 | 状态 |
|---------|------|---------|--------|------|
| BUG-E2E-001 | 通过PowerShell Invoke-RestMethod创建的数据中文显示为"????"乱码 | 低 | 测试数据 | 已确认 |
| BUG-E2E-002 | 普通角色(common)按钮级权限隔离未生效，因DataInitializer分配了所有按钮权限 | 低 | 数据初始化 | 已确认 |

### BUG-E2E-001 详细说明
- **现象**: 用户管理列表中 testuser1 的昵称显示为 "????"，角色管理中测试角色名称也显示为 "????"
- **根因**: 之前 API 级别集成测试使用 PowerShell `Invoke-RestMethod` 提交含中文的 JSON 数据时，编码处理不正确导致中文被存储为乱码
- **影响范围**: 仅影响通过 PowerShell 创建的测试数据，通过浏览器表单提交的中文数据（如"E2E测试用户"）显示正常
- **复现步骤**: 1) 使用 PowerShell Invoke-RestMethod 提交含中文的 JSON → 2) 前端页面查看该数据
- **修复建议**: 清理乱码数据，后续测试通过浏览器表单提交中文

### BUG-E2E-002 详细说明
- **现象**: zhangsan(common角色)登录后，用户管理页面的"新增/编辑/重置密码/删除"按钮均可见
- **根因**: DataInitializer 给 common 角色分配了所有菜单和按钮权限，属于测试数据配置问题
- **影响范围**: 不影响权限隔离代码逻辑的正确性，前端权限指令(v-permission)机制已实现
- **修复建议**: 修改 DataInitializer，给 common 角色分配有限的按钮权限，或创建专门的受限测试角色
