# 根因分析手册

> 质量守护者使用本手册进行问题根因分析和优化方案制定。

---

## 1. 五种根因类型详解

### 1.1 规范缺失
**定义**：该场景在所有规范文档中找不到对应规则。

**判断方法**：
1. 搜索所有guides/*.md，使用关键词搜索
2. 搜索SKILL.md和QUICK_REF.md
3. 搜索Memory中的决策记录
4. 以上均未找到 → 确认为"规范缺失"

**优化方案**：
- 在最相关的guides文档中新增章节
- 更新STANDARDS.md导航索引
- 如为高频规则，写入SKILL.md编码红线和QUICK_REF.md
- 记录到Memory的决策/规范分类

**示例**：
- 问题：AI在分页查询时手动new PageBO+setter
- 分析：05-object-mapping.md中缺少分页对象转换规范
- 优化：在05中新增4.2节分页对象转换规范，新增PageBO.from()工厂方法

### 1.2 规范不清晰
**定义**：规范存在但描述模糊，可导致AI多种理解。

**判断方法**：
1. 找到规范原文
2. 检查是否有明确的"必须/禁止"标记
3. 检查是否有正反例代码
4. 检查是否有歧义表述（如"建议"vs"强制"）
5. AI的理解与用户期望不一致 → 确认为"规范不清晰"

**优化方案**：
- 将"建议"改为"强制"，增加【强制】标记
- 增加正确✅和错误❌代码示例
- 增加具体规则（如从"使用MapStruct"改为"使用MapStruct @MappingTarget更新模式"）
- 增加边界条件说明

**示例**：
- 问题：AI在AppService中抛BusinessException
- 原规范："参数校验使用ParamException"（未明确哪层用哪种异常）
- 优化：改为"AppService格式校验→ParamException(50001)，DomainService业务规则→BusinessException(50002)，AppService禁止抛BusinessException"

### 1.3 规范不可达
**定义**：规范存在但AI无法有效读取（需要3次以上跳转）。

**判断方法**：
1. 从AI视角模拟读取路径：SKILL.md → STANDARDS.md → guides/*.md
2. 计算到达实际规范内容的跳转次数
3. 跳转≥3次 → 确认为"规范不可达"

**优化方案**：
- 将核心规则写入SKILL.md编码红线（0跳转可达）
- 将详细规则写入QUICK_REF.md（1跳转可达）
- 减少导航层级：将深层规范提升到更浅的位置
- 合并或消除纯导航索引文件

**示例**：
- 问题：AI不知道要使用updateDomainFromBO
- 分析：该规则在guides/05-object-mapping.md第4.1节，需要3次跳转（SKILL→STANDARDS→05→4.1节）
- 优化：写入SKILL.md编码红线"更新场景必须用updateDomainFromBO(@MappingTarget)"

### 1.4 AI未读取
**定义**：规范清晰且可达（≤2次跳转），但AI未主动读取。

**判断方法**：
1. 确认规范在SKILL.md或QUICK_REF.md中存在
2. 确认规范有【强制】标记
3. AI仍然违反 → 确认为"AI未读取"

**优化方案**：
- 在SKILL.md的工作流程中增加"编码前必读"步骤
- 在Agent配置中增加强制引用
- 在Memory中增加该规范的记忆条目
- 考虑在代码模板中内嵌规范提醒（注释形式）

### 1.5 偶发错误
**定义**：规范清晰可达，AI读了但犯了单次错误。

**判断方法**：
1. 同类问题仅出现1次
2. 其他同类场景AI遵守了规范
3. 可能是上下文过长导致AI遗忘

**优化方案**：
- 仅记录到Memory，不修改文档
- 避免为偶发错误过度优化文档（防止文档膨胀）

## 2. 根因分析检查清单

对每个质量问题，按以下清单逐项检查：

```
□ 1. 问题描述是否清晰具体？
□ 2. 在哪些规范文档中能找到相关规则？（列出文件和章节）
□ 3. AI到达该规则需要几次跳转？
□ 4. 该规则是否有【强制】标记？
□ 5. 该规则是否有正反例代码？
□ 6. 该规则是否在SKILL.md编码红线中？
□ 7. 该规则是否在QUICK_REF.md中？
□ 8. 同类问题历史出现过几次？（检查Memory）
□ 9. 根因类型判断：[缺失|不清晰|不可达|未读取|偶发]
□ 10. 是否需要优化文档？（同类≥2次或用户要求）
```

## 3. 优化方案模板

根据根因类型选择优化方案：

| 根因 | 优化措施 | 写入位置 | 优先级 |
|------|---------|---------|--------|
| 缺失 | 新增规范章节 | guides/*.md | P1 |
| 缺失 | 新增编码红线 | SKILL.md | P1 |
| 不清晰 | 优化表述+增加示例 | guides/*.md | P1 |
| 不清晰 | 增加编码红线细节 | SKILL.md | P2 |
| 不可达 | 写入编码红线 | SKILL.md | P0 |
| 不可达 | 写入速查表 | QUICK_REF.md | P0 |
| 未读取 | 加强强制机制 | SKILL.md + Agent.md | P1 |
| 偶发 | 仅记录 | Memory | P3 |
