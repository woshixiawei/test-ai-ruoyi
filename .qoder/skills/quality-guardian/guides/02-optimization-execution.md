# 优化执行规范

> 质量守护者使用本规范执行文档/配置优化操作。

---

## 1. 风险分级与审批要求

### 1.1 风险等级定义

| 等级 | 修改对象 | 审批要求 | 理由 |
|------|---------|---------|------|
| 🔴高 | SKILL.md、Agent配置(*.md)、workflow-orchestrator | **必须用户明确同意** | 直接影响Agent行为和工作流 |
| 🟡中 | guides/*.md、STANDARDS.md、QUICK_REF.md | 默认同意，用户可veto | 影响规范内容和可达性 |
| 🟢低 | Memory、技术文档(docs/)、变更记录 | 自动执行，事后通知 | 不影响Agent行为 |

### 1.2 审批流程

```
生成优化提议报告
    ↓
向用户展示提议内容
    ↓
┌─── 🔴高风险修改 ──→ 等待用户明确回复"同意" ──→ 执行
├─── 🟡中风险修改 ──→ 告知用户，48h无异议则执行 ──→ 执行
└─── 🟢低风险修改 ──→ 直接执行 ──→ 事后通知用户
```

---

## 2. 执行顺序

优化修改按以下顺序执行（从低风险到高风险）：

```
1. Memory更新                    [🟢低] — 经验/决策记录
2. 技术文档更新                   [🟢低] — docs/目录下文档
3. guides/*.md规范内容更新         [🟡中] — 具体规范章节
4. STANDARDS.md导航索引更新        [🟡中] — 索引链接
5. QUICK_REF.md速查表更新          [🟡中] — 核心规则速查
6. SKILL.md编码红线更新            [🔴高] — Agent行为定义
7. Agent配置文件更新               [🔴高] — Agent行为定义
8. workflow-orchestrator更新       [🔴高] — 工作流编排
```

---

## 3. 各类型修改的执行规范

### 3.1 guides/*.md 修改规范
- **新增章节**：在文档末尾追加，编号接续现有章节
- **修改章节**：在修改处增加注释说明修改原因
- **禁止删除章节**：如需废弃某规则，改为"已废弃→详见X.X节"而非直接删除
- 修改后更新STANDARDS.md中对应的索引描述

### 3.2 SKILL.md 编码红线修改规范
- 编码红线条目编号连续，新增条目追加到末尾
- 每条红线格式：`**规则名**：具体做法，**禁止行为**`
- 红线总数控制在10-15条（避免过长导致AI不读）
- 新增红线时检查是否与现有红线冲突

### 3.3 QUICK_REF.md 修改规范
- 新增规则时选择正确的章节（1-10）
- 必须包含正确✅和禁止❌的代码示例
- 检查是否需要更新完整AppServiceImpl代码模板

### 3.4 Agent配置修改规范
- 修改前完整阅读原文件
- 仅修改与本次优化直接相关的部分
- 修改后检查引用路径是否正确
- 修改后检查与其他Agent的一致性

### 3.5 Memory更新规范
- 问题记录写入"常见问题经验"分类
- 决策记录写入"重要决策"分类
- 编码规范写入"代码编写规范"分类
- 更新时使用keywords便于后续检索

---

## 4. 执行后验证检查清单

每次优化执行后，按以下清单验证：

```
□ 1. 读取修改后的文件，确认内容正确
□ 2. 检查SKILL.md编码红线是否包含新规则
□ 3. 检查QUICK_REF.md是否同步更新
□ 4. 检查STANDARDS.md导航索引是否同步更新
□ 5. 检查文件间引用路径是否正确
□ 6. 检查是否存在重复描述（同一规则在多处出现时确保一致）
□ 7. 在STANDARDS.md变更记录中追加本次优化
□ 8. Memory中记录本次优化决策
```

## 根因分析
- 根因类型: [缺失/不清晰/不可达/未读取/偶发]
- 详细分析: [描述]

## 执行的优化措施
| # | 措施 | 修改文件 | 风险等级 | 状态 |
|---|------|---------|---------|------|
| 1 | [描述] | [文件路径] | [高/中/低] | ✅已执行 |

## 验证结果
- [ ] 文档内容正确
- [ ] 交叉引用一致
- [ ] 编码红线已更新

- [ ] 变更记录已追加

- [需要观察的后续场景]
- [预期的效果指标]
